# 食光 · eatWhat

原生微信小程序：选择家里的食材 → 查看能做的菜 → 按用量和步骤做饭。

## 本地体验

微信开发者工具打开本目录并点击“编译”，不需要启动后端或登录。

建议首次体验：选择鸡蛋、西红柿 → 在“常备调料”中点“我有油、盐、生抽” → “看看能做什么” → 西红柿炒鸡蛋。
也可以只选鸡蛋，查看缺少的材料并加入买菜清单；买好勾选后点击“收好已买的”，推荐结果会随已有食材更新。

## 已实现

- 食材分类、多选、名称和别名搜索；未覆盖食材显示“菜谱待补充”。
- 主料与必需调料都参与匹配，所有材料初始均不默认已有。
- 推荐分为现在能做、差一两样、多补几样；至少拥有一道菜的一种主料才推荐。
- 按 15 分钟内、不吃辣、烹饪工具筛选；1—4 人用量换算。
- 44 道完整菜谱，包含主料、必需调料、可选材料、分步做法和提示。
- 收藏、从材料齐全的菜里随机选择、待买材料去重、已购材料收入已有食材。
- 做饭模式屏幕常亮，逐步勾选，离开页面时关闭常亮。
- 本地持久化；登录后按账号同步冰箱、清单和收藏；不自动扣减库存。
- 微信登录后可选择或更换头像（微信头像 / 相册照片 / 拍照），头像上传到服务端，换设备也能看到。

## 数据与目录

- `data/ingredients.js`：现有食材字典。`pantry` 仅为历史元数据，不代表用户已拥有。
- `data/dishes.js`：原样例草稿及新增菜品索引，保留用于后续扩充，不直接作为上线菜谱。
- `data/recipes.js`：当前实际使用的 44 道完整菜谱，独立维护家常省事版的必需材料、可省材料和步骤。
- `utils/kitchen.js`：匹配、筛选、用量换算、本地存储、买菜清单。
- `pages/index`、`pages/results`、`pages/recipe`、`pages/shopping`：主流程页面。
- `tests/kitchen.test.js`：核心匹配和页面流程回归测试。

当前规则以精确食材 ID 匹配：别名搜索定位同一食材，但不把普通猪肉视为里脊，不把尖椒自动视为不辣青椒。可选配料不影响“现在能做”。份量判断只比较材料种类，不保证库存数量充足。

买菜清单按品类合并；购买数量请参照菜谱和家中实际余量。该版本不声称精确合计多道菜的采购数量。

## 后端

现有 Laravel 后端及 `utils/api.js`、`app.js` 登录配置保留。本版使用本地菜谱，后端不参与推荐。
后续需要统一菜谱管理、账号同步收藏时，再接入后端接口。

旧方案 `docs/design-fridge-picking.md` 是历史设计，常备材料默认拥有等规则已被本版替代。

## 登录与头像

「我的」页登录用微信「头像昵称填写能力」：`<button open-type="chooseAvatar">` 点开就是头像选择面板（微信头像 / 相册 / 拍照）。
回调给的是**本机临时路径**，必须上传到后端换成稳定地址，否则换设备或清缓存后就是裂图。

- 未登录时主按钮点开选择面板，选完自动登录并上传头像；面板点取消不触发回调，所以下面留了「跳过头像，直接登录」。
- 已登录时头像块本身就是选择按钮，右下角 ✏️ 提示可点更换。
- 头像地址后端只下发 `/storage/xxx` 相对路径，小程序按自己的 `baseUrl` 拼接，开发机和生产域名都不用改配置。
- 真机生效需要在小程序后台把生产域名加进 `uploadFile 合法域名` 和 `downloadFile 合法域名`，并确认隐私指引已声明「用户信息（头像、昵称）」。

细节与发布顺序见 `docs/avatar-login.md`。

## 产品偏好：家常、省事、少买材料

用户明确要求：能吃、好吃就行，不追求餐馆式完整配料。能省的材料要标为“可不放”，说明省略的影响；不能因缺淀粉、装饰葱花、增香辅料而阻止推荐。青椒肉丝只需青椒、肉、油、盐，淀粉、生抽、蒜可省。

可选材料不参与缺料判断、不自动加入采购清单，做法必须给出不用它也能完成的路径。保留菜品关键风味材料，例如醋溜土豆丝的醋、蒜蓉菜的蒜、可乐鸡翅的可乐；不能为了减少缺料而忽略食材熟透等必要步骤。

## 简约导航

底部原生 Tab 为“做什么、买什么、我的”。收藏入口“想吃的”位于“我的”菜单，常备调料可在首页或“我的”进入设置。首页只展示食材文字标签，筛选和已选明细默认折叠，人数设置保留在菜谱详情。推荐默认两组：现在能做、补一点就能做；缺料较多的菜手动展开查看。

## 基础菜覆盖

首页常用的 12 种食材，每种都有只用这一种主料和基础油盐即可完成的菜。豆腐有香煎、清炖、炒碎三种基础做法；未勾选必需油盐时仍明确提示缺料，不把用户没选的调料默认为已有。已增加常用单食材覆盖及豆腐快手筛选、结果分组回归检查。

## 一键补料

推荐卡片直接点击“＋ 加入清单”，不跳转详情；成功后显示“已加入 ✓”。共用缺料按品类合并、可省材料不加入，已勾选的购买状态不会被重复加入重置。清单角标显示未买品类数；勾选、移除、收入已有食材时更新。详情页缺料时主按钮直接补料，加入后可进入清单，材料齐全时显示“开始做饭”。

## 我的冰箱

- “做什么”切换“我的冰箱 / 选食材”；库存与临时食材选择独立保存。
- 冰箱按冷藏、冷冻、冰箱外分组显示食材、数量和单位。点食材可增减、修改数量位置、标记用完。
- “放入食材”支持搜索、多种材料批量入库。数量留空为“没数过”，不会默认成 1。
- 买菜清单勾选后进入数量确认页，确认成功才清除对应已购条目并显示冰箱。取消或保存失败保留原清单。
- 同食材、单位、位置的数量累加；不同单位/位置分开存放；含未知数量时总数保持未知。修改库存填写的是修改后的总量。
- 之前选中的主料不会自动冒充库存，首页提供确认后批量导入。库存中的调料与常备调料联动。
- 推荐依据库存的食材种类与常备调料，暂不自动换算单位或判断数量是否足够；界面提示做前核对用量。
- 不自动扣库存、不做保质期提醒；用完可手动减量或标记。库存保存在本机。
- 库存服务：utils/inventory.js；入库页：pages/stock/stock。
