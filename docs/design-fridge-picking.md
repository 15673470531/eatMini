# 冰箱配菜 — 数据与匹配规则设计（v1，待确认）

抖音「这顿不发愁」类选菜小程序，第一功能模块「冰箱配菜」的数据结构与匹配规则。

项目位置：
- 前端 `/Users/guoqing/WeChatProjects/eatWhat`（数据文件在本项目 `data/`，本文档在 `docs/`）
- 后端 `/Users/guoqing/PhpstormProjects/eatWhat`（Laravel 12，复制自通用骨架 `laravelBase`）

## 一、当前产出

- `data/ingredients.js` — 98 项食材，其中 30 项标记为「常备」
- `data/dishes.js` — 26 道菜品样例
- 这两个文件是 `module.exports = {...}` 形式的 **JS 模块**（小程序 `require` 不支持 `.json`），
  去掉首行前缀即为合法 JSON，可直接用于后端 seeder
- 数据定位：**前端静态 JSON**，MVP 阶段零请求直接读，后端暂不参与菜品下发

已通过校验：无悬空引用（菜品引用的食材 id 全部存在）、无名称/别名冲突。

## 二、已定决策

1. **输入方式：方案 B 打底 + 方案 A 换壳**
   即先用平铺食材网格勾选跑通功能，之后把可视化冰箱分格做成同一套勾选逻辑的视觉壳。
   ⚠ 此决策是在用户未回复时按推荐值代定的，需用户确认或推翻。
2. **调料、葱姜蒜、常备干货 一律不参与「缺少」判定**（`pantry: true`）。
   否则每道菜都会显示「缺 8 样」，体验直接崩。
3. **第一版不用实拍图**：用食材 emoji + 纯文字卡，零版权风险、零美术成本。
4. **结果用三档分级，不用匹配度百分比**。评分不精确最招黑，用确定性文案（「还差一样：香菇」）。

## 三、字段说明

### ingredients.json

| 字段 | 说明 |
| --- | --- |
| `id` | 稳定英文 id，不用中文名当 id |
| `name` | 显示名 |
| `aliases` | 别名数组，用于用户搜索/勾选时的归一化 |
| `category` | 蔬菜/菌菇/豆制品/肉禽/蛋奶/水产/主食/干货/加工肉/其他/调料 |
| `parent` | 泛化父级食材 id。用于「菜品要父级、用户勾了子级」的向上匹配 |
| `pantry` | true = 默认家庭常备，永不判缺 |

### dishes.json

| 字段 | 说明 |
| --- | --- |
| `id` / `name` / `emoji` | 标识与展示 |
| `required` | **必需主料**，只有这些参与缺失判定 |
| `optional` | 可选辅料，有更好、没有也能做 |
| `seasonings` | 调料，仅展示，不判定缺失 |
| `tags` | 口味/属性（快手/素/荤/汤/辣/兜底 等）。二期「多日餐食计划」用来做菜单平衡（不能一周全是辣） |
| `timeMin` / `difficulty` | 耗时（分钟）/ 难度 1-3 |
| `steps` | 3-6 步骨架，不做完整菜谱库 |

## 四、匹配规则

```
输入：用户勾选的食材集合 S（已按别名归一化为 id）

对每道菜 d，计算缺失列表 miss：
  对 d.required 中每个 r：
    若 r 是常备(pantry)       → 视为有
    若 r ∈ S                  → 有
    若 S 中存在 s 且 s.parent == r → 有（勾了子级，父级菜品可用）
    否则 → miss += r

分级：
  miss 为空                                    → 「现在就能做」
  len(miss) == 1 且 len(d.required) >= 2       → 「还差一样：<菜名>」（附「加入买菜清单」）
  其他                                          → 「差得多」（默认折叠）
```

### 关键规则修订（由实测发现）

**单主料菜缺料不算「差一样」。**

原规则「缺 1 样就算差一样」有缺陷：红烧肉只有五花肉一个必需主料，缺了五花肉就 100% 做不了，
却会被归进「差一样」，污染列表。同理蒜蓉生菜、红烧茄子、凉拌黄瓜、清炒西兰花、蒜蓉虾仁、蛋炒饭。

修订：`len(miss) == 1` 之外，追加 `len(d.required) >= 2`。

### 反向泛化不成立（有意保守）

菜品要「五花肉」，用户只有「猪肉」→ 判缺。
菜品要「猪肉」，用户有「五花肉」→ 判有。
理由：五花肉能做红烧肉，但普通猪肉不一定能替。

## 五、实测数据（真实跑出来的）

三组输入场景，对比修订前后的「差一样」列表长度：

| 场景 | 能做 | 老规则 差一样 | 新规则 差一样 |
| --- | --- | --- | --- |
| 只勾鸡蛋 | 3 道 | 11 道 | **4 道** |
| 家常一套 9 样（土豆/青椒/五花肉/鸡翅/豆腐/白菜/面条/可乐/香菇） | 3 道 | 15 道 | **7 道** |
| 西红柿+鸡蛋+土豆+白菜+米饭 | 7 道 | 9 道 | **3 道** |

「只勾鸡蛋」新规则下的「差一样」：西红柿炒鸡蛋(缺西红柿)、番茄鸡蛋汤(缺西红柿)、蛋炒饭(缺米饭)、洋葱炒鸡蛋(缺洋葱)
—— 全都是有意义的推荐，不再混入「红烧肉缺五花肉」这类无效项。

泛化与别名验证：
- 勾「五花肉」→ 红烧肉 命中 ✔
- 勾「猪肉」→ 红烧肉 不命中 ✔（符合保守设计）
- 勾「鸡腿 + 香菇」→ 黄焖鸡 命中 ✔
- 别名归一：番茄→西红柿、马铃薯→土豆、排骨→猪排骨 ✔
